* このファイルの見方

このファイルは、同じような TODO を並べるのではなく、
Org mode の各機能が「何のためにあるのか」を見比べるためのサンプル。

- =TODO / NEXT / WAIT= :: タスクの状態
- =SCHEDULED= :: 取り組む予定日
- =DEADLINE= :: 終了期限
- タグ :: プロジェクトをまたいで検索・絞り込みするためのラベル
- =PROPERTIES= :: その見出しに持たせる追加情報
- =EFFORT= :: 作業時間の見積もり
- =CLOCK= :: 実際に作業した時間
- 繰り返し指定 :: 定期タスク
- Archive :: 終わった項目を普段の一覧から退避する

* Projects

** Emacs 改善                                                          :emacs:
:PROPERTIES:
:CATEGORY: Development
:END:

親見出しに =:emacs:= タグを付けているため、
子タスクを Emacs 関連としてまとめて扱える。

*** NEXT [#A] Agenda の表示を整える
SCHEDULED: <2026-10-14 水 15:00>
DEADLINE: <2026-10-16 金>
:PROPERTIES:
:EFFORT:   1:30
:OWNER:    Takashi
:END:

このタスクは、

- 10/14 に取り組む予定
- 10/16 が締切
- 見積もりは 1時間30分
- =OWNER= は自由に付けたプロパティ

という情報を持つ。

CLOCK は「予定」ではなく、実際に作業した時間。

CLOCK: [2026-10-14 水 15:10]--[2026-10-14 水 15:55] =>  0:45

*** WAIT [#B] org-super-agenda の挙動を確認する                       :research:
:PROPERTIES:
:EFFORT:   0:30
:END:

=WAIT= は「今すぐ自分が進める状態ではない」ことを表す例。
=:research:= を使えば、Emacs 以外の調査タスクと横断して探せる。

*** DONE [#C] README を更新する
CLOSED: [2026-10-13 火 18:30]
:PROPERTIES:
:EFFORT:   0:20
:END:
CLOCK: [2026-10-13 火 18:05]--[2026-10-13 火 18:25] =>  0:20

* Schedule と Deadline の違い

** TODO 請求書を作成する
SCHEDULED: <2026-10-15 木>

これは「10/15 にやる予定」。
締切そのものは設定していない。

** TODO 請求書を提出する
DEADLINE: <2026-10-20 火>

これは「10/20 までに終わらせる必要がある」。
いつ着手するかは指定していない。

** TODO レポートを提出する
SCHEDULED: <2026-10-16 金>
DEADLINE: <2026-10-20 火>

「10/16 に着手し、10/20 までに終える」のように両方を持たせることもできる。

* 繰り返しタスク

** TODO 毎週の振り返り                                              :review:
SCHEDULED: <2026-10-14 水 +1w>
:PROPERTIES:
:EFFORT:   0:30
:END:

DONE にすると次回の日付へ進む、毎週の定期タスクの例。

** TODO 月次バックアップ                                             :maintenance:
SCHEDULED: <2026-10-31 土 +1m>

毎月繰り返す例。

* Tags の使い方

タグは「所属先」よりも「あとで横断して取り出したい特徴」に使うと便利。

** TODO Emacs の不具合を調べる                                     :emacs:research:
** TODO RAG の論文を読む                                           :rag_lab:research:
** TODO Python の処理を書く                                        :rag_lab:coding:
** TODO Emacs Lisp を修正する                                      :emacs:coding:

例えば Agenda のタグ検索では、

- =research= :: 調査系だけ
- =coding= :: 実装系だけ
- =emacs= :: Emacs 関連だけ
- =emacs+coding= :: Emacs かつ実装系

のように、ファイルやプロジェクトをまたいで絞り込める。

* Properties の使い方

** TODO 小さな機能を実装する
:PROPERTIES:
:EFFORT:   0:45
:OWNER:    Takashi
:PROJECT:  Emacs
:CONTEXT:  Home
:END:

=EFFORT= は Org が時間管理に利用できるプロパティ。
=OWNER= / =PROJECT= / =CONTEXT= は、このサンプルでは自由に作ったプロパティ。

値を持つ情報は、タグより Property の方が向いている。

例:

- タグ: =:research:= のような「該当する / しない」
- Property: =:EFFORT: 0:45= のような「名前と値」

* Clock と Effort

** TODO テーマを調整する
:PROPERTIES:
:EFFORT:   2:00
:END:
CLOCK: [2026-10-14 水 09:00]--[2026-10-14 水 10:10] =>  1:10
CLOCK: [2026-10-14 水 11:00]--[2026-10-14 水 11:35] =>  0:35

見積もり:

#+begin_example
EFFORT = 2:00
#+end_example

実績:

#+begin_example
CLOCK 合計 = 1:45
#+end_example

=Effort= と =Clock= を一緒に使うと、
「2時間の見積もりに対して、実際は1時間45分だった」のように比較できる。

* 記録用タイムスタンプ

<2026-10-14 水>

Agenda の予定として扱われる。

[2026-10-14 水]

作成日・更新日・記録など、
Agenda に予定として出したくない日時に向いている。

* Archive

** DONE 完了して普段は見なくてよい作業
CLOSED: [2026-10-01 木 12:00]

Archive は削除ではない。

完了した subtree を普段の作業ファイル・Agenda から外し、
履歴として別の場所へ退避するために使う。

そのため、

- 通常の Agenda を過去の DONE で埋めない
- 必要なら後から履歴を調べられる
- grep / ripgrep などでは archive ファイルも検索できる

という使い方になる。

* 日付のない Backlog

** TODO いつか試したい Org Capture
** TODO Column View を試す
** TODO Agenda のカスタムコマンドを調べる

日付を付けない TODO は、
「いつやるかはまだ決めていないが、忘れたくないもの」として残せる。

Agenda の日付表示には出なくても、TODO 一覧では確認できる。

* Column View

このファイル先頭の =#+COLUMNS:= により、
タスクを表形式で見るための列を定義している。

#+begin_example
Task | TODO | Priority | Tags | Estimate | Actual
#+end_example

見出し階層を保ったまま、
Property や Clock の情報を一覧で確認したいときに使える。
